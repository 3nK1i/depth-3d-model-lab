## 2. Frozen I6.8 telemetry contract proposal (for implementation in I6.8A/B–F)

**Separation of concerns.** A new Qt-free job-observation contract, e.g. `eia.reconstruction.job_telemetry.v1`, is operational evidence only. It never writes SfM pose, changes dense-provider selection, grants metric scale, updates final admission, creates a scene, controls cancellation, or persists/reopens a run.

**Identity.** Every event carries a canonical offline `session_id`, `job_kind` (`offline_sfm` or `post_sparse_dense`), and a dedicated `dense_run_id` for dense jobs. A unique attempt identity is necessary when retry/recovery becomes supported in I6.9; no event from a prior run or different session may affect the current UI. Include producer identity, schema version, monotonically increasing producer sequence, UTC observation time, and host receipt time for staleness decisions. Do not compare unrelated process-local monotonic clocks as if guaranteed comparable.

**Status and stage.** Report factual `starting`, `running`, `verifying`, `completed`, `failed`, `cancelled` states and specific observed substage names. The controller's existing terminal lifecycle remains authoritative. If the worker has no fresh milestone, retain the last confirmed stage and display elapsed time plus a visibly stale/unavailable observation; never infer advancement from elapsed time or resource use.

**Progress evidence.** Keep the existing legacy `progress_fraction` UI for backward compatibility but label it as an *estimated workflow indicator*, not measured job completion. The new telemetry may show exact stage counters such as registered images or observed completed depth maps with provenance; distinguish `image started` from `image completed`. No overall percentage or ETA is generated from file counts, stage weights, or `Fusing image [n/N]`. Final 100% / "complete" is driven only by existing terminal acceptance and independent dense verifier.

**Resource metric definitions.** Use explicit metric name, value, unit, scope (`process`, `process_tree`, `system`, `gpu_device`, or `gpu_process`), GPU index when relevant, observation time, and availability (`observed`, `unavailable`); the controller marks outdated samples stale in I6.8D without fabricating a zero. Report worker RSS as worker RSS; report process-tree RSS only if children were actually sampled; label global GPU device VRAM/utilization as device-wide, not job utilization. Unavailable sensors are `null`/unavailable, never zero. Sample disk free space on the actual reconstruction output filesystem; avoid reading 20-GiB evidence files to update telemetry.

**Transport and UX policy.** Deliver small, bounded, independently typed telemetry observations through existing Qt-owned workers and controller composition. Samplers run away from the GUI thread; subprocess-based probes must have timeouts. Set a bounded cadence, latest-only coalescing, strict event and string size limits, stale-session/old-sequence rejection, and no unbounded in-memory history. Keep one concise job progress/resource panel with progressively disclosed detail, instead of continuously appending log text. Design sampling interval and limits empirically in I6.8C/D; do not commit speculative performance thresholds during this inspection.

## 3. Exact substep execution order and gates

- **I6.8A (this contract-only patch):** inventory and a Qt-free validated observation/wire schema with per-producer sequencing and job/run identity, a bounded resource-reading model and negative tests. The source inspection itself was read-only; this patch adds only the new contract/tests/runner/documentation. It does not connect or enable any telemetry in production.
- **I6.8B:** instrument real SfM/MVS stage messages and adapt them to the new Qt-free progress contract (with tests-first red/green). Preserve the current SfM camera authority, dense preview, and admission protocols. Prove that no fusion/image-count heuristic is presented as completion/ETA.
- **I6.8C:** implement non-blocking, attributable RAM/CPU and device-vs-process GPU/VRAM readings with explicit unavailability; bounded disk and sampler costs; test PID reuse/child-exit and sensor-failure cases.
- **I6.8D:** wire Qt transport, identity isolation, rate limiting, bounded retention and process terminal flush; test foreign, stale, duplicated, out-of-order and malformed events plus worker-exit races.
- **I6.8E:** bind a compact main-page panel, label estimated and observed values, and test idle, running, stale, failed and completed UI states. Keep dense final display separate from telemetry authority.
- **I6.8F:** run focused/regression/stress tests and a bounded UI/live-runtime probe only if required. Measure actual telemetry sampling overhead and the impact on GUI responsiveness; record unavailable metrics explicitly. Commit/push a validated checkpoint to the existing Gitea development branch.

## 5. Evidence and limits

This assessment was grounded in a **source-only ZIP**. Its archive SHA256 and ZIP structure were checked. A new isolated telemetry contract and unit tests were created separately and verified against the extracted source, **not** applied to the user's repository. The new contract does not import Qt, start workers, read reconstructed data, sample GPUs or change admission. Tests-first proof: importing the absent contract failed at collection (red); after implementing it, 77 tests passed across the new unit tests and the predecessor I6.6A/I6.7A contracts (green). Python compilation passed. No live GPU/Qt UI was run here because this inspection environment does not have PyQt6 or VisPy. The previous TempleRing and South Building qualification results remain unchanged. Validate this narrow patch and its clean Git scope in the user's `depth` environment before commit/push.

## 6. New contract files and limitations

- `core/reconstruction/reconstruction_job_telemetry_contract.py`: bounded `EIA_JOB_TELEMETRY ` JSON-line payload, strict stage-to-job/counter binding, canonical sparse session and dense run UUIDs, independent per-producer sequence gating, and explicit device-wide versus process-attributed resource scope.
- `tests/unit/test_i6_8a_job_telemetry_contract.py`: round-trip, authority-spoof/ETA rejection, stale/foreign/duplicate/out-of-order identity, invalid units/counters, malformed/nested payloads, and resource-scope tests.
- `scripts/run_i6_8a_tests.sh`: narrow new and predecessor contract tests, with Python compile check.

**Not yet implemented:** source-worker instrumentation, telemetry sampling, GUI transport, stale-value timing, resource history, telemetry UI and runtime overhead qualification. These are I6.8B–F, in that order. The contract does not itself prove that a producer honestly measured a value: the sampler and supervisor integrations must supply and qualify that evidence. Do not use its `JobTelemetryObservation` to claim final SfM/MVS admission, certified measurement, or a persistent scene.
