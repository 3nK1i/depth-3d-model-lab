# I4.3E2 — UniDepthV2 Production Provider Adapter

Status: implementation candidate; authoritative workstation binding required before closure.

## Scope

I4.3E2 binds the existing UniDepthV2 image-model runtime to the canonical I4.3A offline `single_image_depth` provider contract. It does not redesign or replace the interactive UniDepthV2 adapter.

The provider is explicit-selection only in this phase. Auto selection remains deferred. All registered SfM views are available by default; adaptive view selection belongs to I4.3F and no permanent production view cap is introduced.

## Native UniDepthV2 semantics preserved

- native depth: metric model evidence;
- native intrinsics: model-predicted, with the registry's estimated fallback when unavailable;
- native direct 3D points: retained as model evidence only;
- native confidence channel: relative uncertainty, lower is better;
- source checkout pin: `8d8cfe4c7ee15297099983607febf0d4f32eb3d6`;
- hardware-adaptive variants remain the existing registry policy: ViT-S/14, ViT-B/14, ViT-L/14.

The raw uncertainty is **not** treated as a `[0,1]` confidence. Canonical fusion derives a monotonic weight using `1 / (1 + uncertainty)` while retaining the raw uncertainty artifact.

## Authority locks

PyCOLMAP SfM remains the sole authoritative global frame and camera-pose source. Canonical geometry is generated by aligning UniDepthV2 depth evidence to the authoritative SfM gauge and reprojecting with the SfM camera model/poses.

The provider explicitly does **not**:

- consume UniDepthV2 direct points as canonical geometry;
- consume model-predicted/fallback intrinsics for canonical projection;
- promote native metric depth into physical canonical metric scale;
- establish measurement authority or certified metrology;
- generate or authorize a surface mesh;
- promote UniDepthV2 over another provider.

Per-view sparse-correspondence scale alignment maps independent single-image depth into the arbitrary SfM reconstruction gauge. This alignment is not a physical scale qualification.

## Qualification state

UniDepthV2 remains `candidate`. Cross-provider scenario qualification is deferred to I4.3G, and robustness/selection evidence remains later work. Its existing registry license status `noncommercial_review_required` is preserved in the E2 provider metadata; E2 does not alter licensing policy.

## Validation gates

`bash scripts/run_i4_3e2_tests.sh all` runs the closed E1/D1-D3 matrix, existing UniDepthV2 adapter/runtime regression, new E2 unit/integration/stress tests, and a lazy-worker/source-pin probe.

Formal E2 closure additionally requires the execution-free workstation binding smoke against the real passing I4.3A, I4.3D3, and I4.3E1 evidence snapshots. Heavy UniDepthV2 inference is not required merely to establish the production-provider binding.
